    Inside a computer

    Lecture L1

    A computer is a very fast, very obedient kitchen. Ingredients come in, a chef follows a recipe exactly, and a dish goes out.

    Every computer, from your phone to a supercomputer, does the same three things: it takes input, it processes it, and it gives output. This is the IPO model. Computer organization is the study of the parts that make this happen and how they are wired together.

    The input unit (keyboard, mouse, sensor) converts what you do into binary, the 0s and 1s a machine understands. The central processing unit (CPU) is the chef. Inside it, the control unit (CU) reads each instruction and directs traffic, the arithmetic logic unit (ALU) does the maths and the comparisons (is A greater than B?), and registers are tiny, ultra-fast slots that hold the values being worked on right now.

    The memory unit is the kitchen counter. Main memory (RAM) holds the program and its data while it runs, and it forgets everything when power goes off. That is why RAM is called volatile. Secondary storage (SSD, hard disk, pen drive) is the store room: slower, but it keeps your files permanently. The output unit (screen, printer, speaker) turns results back into something humans can use.

    One big idea ties it together: the program's instructions and its data both live in the same memory. This is the stored-program concept (often called the von Neumann architecture), and it is why you can load a new program without rewiring the machine.

    Follow 2 + 3 through the machine

    Traps that cost marks

    • RAM is volatile, ROM is not. ROM holds start-up instructions that must survive power-off.
    • The CPU does not store your files. Files live in secondary storage; the CPU only works on what is in registers and memory.
    • Comparisons such as A > B are done by the ALU, not the control unit. The "L" in ALU stands for logic.

    From switches to C

    Lecture L2

    Talking to a computer in binary is like ordering food by spelling every word in Morse code. Languages were invented so we could just say what we want.

    The first computers of the 1940s had no operating system. Programmers booked the whole machine, set switches or plugged cables by hand, and ran one job at a time. An operating system (OS) is the manager that sits between you and the hardware: it loads programs, shares the CPU and memory, and handles files and devices. Here is how it grew up.

    1940sNo OS. Switches, plugboards, one person at a time.
    1950sBatch systems. Jobs on punched cards run one after another without a human in between.
    1960sMultiprogramming and time-sharing. Many programs and users share one CPU.
    1969 to 73UNIX is born, then rewritten in C so it can move to new machines.
    TodayWindows, Linux, macOS, Android: all descendants of these ideas.

    Languages climbed a similar ladder. Machine language is pure binary. The CPU runs it directly, so it is fast, but it is nearly unreadable and works only on the processor it was written for. Assembly language replaces binary with short words called mnemonics, such as MOV and ADD; a translator called an assembler turns it into machine code. High-level languages like C, Python and Java read almost like English and run on many machines. A compiler translates the whole program at once (that is what C uses), while an interpreter translates and runs it line by line (Python does this).

    One instruction, three languages: add a and b, store in sum

    1.3
    Thinking in steps: algorithms
    Lecture L3 with tutorial T1
    
    
    Google Maps never says "just get there". It says turn left in 200 metres. An algorithm is directions that a machine can follow without guessing.
    
    
    
    
      
    Using a computer to solve a problem matters because a computer is fast, never gets bored, and does exactly what it is told, every time. That last part is also the catch: it does exactly what it is told, so the instructions must be perfect. Those instructions, written before any code, are the algorithm.
    
      
    A good algorithm has five properties. It is finite (it stops after a limited number of steps), definite (each step has one clear meaning), it takes zero or more inputs, produces at least one output, and every step is effective, meaning basic enough to be done with pen and paper.
    
      
    You can represent an algorithm three ways: in plain numbered English, in pseudocode (English with programming shape, like IF and REPEAT), or as a flowchart, which is the next lesson.
    
    
    
    
    
    
    
      
    Worked example: a logical problem
    
      
    Find the largest of three numbers A, B and C.
    
      
    Step 1: Start
Step 2: Read A, B, C
Step 3: If A > B and A > C, then LARGEST ← A
Step 4: Else if B > C, then LARGEST ← B
Step 5: Else LARGEST ← C
Step 6: Print LARGEST
Step 7: Stop
    
      
    Dry run it with A = 4, B = 9, C = 2
        
    Step 3: is 4 > 9? No, so skip. Step 4: is 9 > 2? Yes, LARGEST becomes 9. Output: 9. Dry running with real numbers is how you catch mistakes before writing code.
    
    
    
    
    
      
    Worked example: a numerical problem
    
      
    Simple interest, where SI = P × R × T / 100.
    
      
    Step 1: Start
Step 2: Read P, R, T
Step 3: SI ← (P × R × T) / 100
Step 4: Print SI
Step 5: Stop
    
    
    
    
    
      
    Your turn: put the "swap two numbers" algorithm in order
    
      
    Use the arrows to move each step. The trick is the third variable, TEMP, which holds A safely while A is overwritten.
    
      
      
      
      
      
      
    
      
    
      
      
      Traps that cost marks
      
      
        
        
      • Vague steps such as "calculate the result" break the definiteness rule. Say exactly what is computed.
        • 
        
      • Forgetting Start and Stop. Examiners look for both.
        • 
        
      • Using a value before reading it. Input always comes before the step that uses it.
        •

      1.4
      Flowcharts and RAPTOR
      Lecture L4
      
    
      A flowchart is an algorithm you can see. Shapes tell you what kind of step it is; arrows tell you where to go next.
      
    
    
      
      
      Each shape has one job. An oval marks Start and Stop. A parallelogram means input or output (read or print). A rectangle is a process, usually a calculation or assignment. A diamond asks a yes or no question and has exactly two exits. A small circle is a connector, used when a chart continues somewhere else on the page.
      
      
      Four rules keep a flowchart readable: one Start and one Stop, arrows flow top to bottom (or left to right), every decision has both exits labelled, and lines should not cross if you can avoid it.
      
      
      RAPTOR (Rapid Algorithmic Prototyping Tool for Ordered Reasoning) is a free tool where you draw a flowchart and then run it. It uses six symbols: assignment, call, input, output, selection and loop. Because it executes your drawing step by step and shows the variable values, you find logic mistakes before you have written a single line of C.
      
    
      
    
      

    
      
      
      Build it, then run it: is a number even or odd?
      
      
      Step 1: pick the correct shape for each step. Step 2: once all seven shapes are right, type a number and watch the flowchart run, just as RAPTOR would.

      1.5
      Your first C program
      Lecture L5
      
    
      C is the language that operating systems, phone firmware and car engines are written in. Learn it and you understand how software meets hardware.
      
    
      
      
      1967BCPL, by Martin Richards.
      
      
      1970B, by Ken Thompson at Bell Labs.
      
      
      1972C, by Dennis Ritchie at Bell Labs.
      
      
      1973UNIX rewritten in C.
      
      
      1989ANSI standardises C (C89).
      
    
      
    
      
      
      C is popular for good reasons. It is fast because it sits close to the hardware. It is portable, so the same code compiles on many machines. And it is small: a few keywords and a powerful standard library. Here is the classic first program, line by line.
      
    
      

      #include <stdio.h>          // preprocessor: bring in printf from the standard I/O library

int main(void)              // every C program starts running here
{                           // opening brace: body begins
    printf("Hello, World!\n"); // print text; \n means new line; ; ends the statement
    return 0;               // tell the OS: finished successfully
}                           // closing brace: body ends
      
    
      A second program reads input. scanf needs the & sign before each variable so it knows where in memory to put the value. You will understand that fully in Unit 4, with pointers.
      

      #include <stdio.h>
int main(void)
{
    int a, b, sum;
    printf("Enter two numbers: ");
    scanf("%d %d", &a, &b);   // %d means "an integer goes here"
    sum = a + b;
    printf("Sum = %d\n", sum);
    return 0;
}
      
    
      Predict the output: printf("Hi\nThere");
      
      Two lines: Hi on the first and There on the second. The \n is one character, a newline, not two letters.
      

    
      
      
      What happens when you type gcc hello.c -o hello
      
      
      
      
      
      
      
      
      
      
      
    
      
    
      
      
      Two file types confuse everyone. Object code (hello.o, or hello.obj on Windows) is machine code for your file only. It still has holes, such as "call printf, address unknown". The linker fills those holes with code from the C library and produces executable code (hello, a.out or hello.exe) that the OS can load and run.
      
      
      When something goes wrong, ask which kind of error it is. A syntax error breaks the grammar of C, such as a missing semicolon or a misspelled keyword. The compiler catches it and refuses to build. A logical error compiles and runs happily but gives the wrong answer, because the algorithm itself is wrong. The compiler cannot catch those. Only testing with known answers can.
      
    
      
    
      
      
      Error detective: syntax or logical?
      
      
        
    
        
    
        
      
        Traps that cost marks
        
      
          
        
        • C is case-sensitive. Printf, Main and Int are all wrong.
          • 
        
        • Forgetting & in scanf("%d", &a). It compiles, then crashes or reads garbage.
          • 
        
        • "No compiler errors" does not mean "correct program". Logical errors hide there.
          •
